Proyecto Final — BD1

Sistema de Estadísticas
Fórmula 1

Base de datos + API REST + Frontend interactivo

MySQL 8.0 Spring Boot 3 React 18 TypeScript VirtualBox Full-Stack

Descripción del Proyecto

Sistema de información que modela el funcionamiento de la Fórmula 1 — pilotos, equipos, circuitos, temporadas, carreras, sesiones y reglamentos — y permite obtener resultados y estadísticas de forma consistente a partir de ese modelo.

El dominio cubre: catálogo de pilotos, equipos, circuitos y temporadas; registro de Grandes Premios (GPs, sprints, clasificaciones); resultados por sesión (posición, vueltas, tiempos, abandonos); estadísticas derivadas (podios, victorias, poles, vueltas rápidas); campeonatos y clasificaciones (standings de pilotos y constructores, evolución carrera a carrera); y trazabilidad analítica (rendimiento por circuito, head-to-head, tendencias por temporada).

El proyecto fue desarrollado como trabajo final de Bases de Datos I en la Universidad El Bosque, aplicando el ciclo completo de diseño: desde el modelo MERE hasta la implementación full-stack con una VM dedicada.

Frontend — React 18 + TypeScript

Aplicación SPA con Vite, Material UI v7, Recharts para gráficas de estadísticas, React Router para navegación y Context API para estado global.

Backend — Spring Boot 3 + Java

API REST con Spring Data JPA / Hibernate, documentación automática con SpringDoc OpenAPI (Swagger UI) y arquitectura en capas (Controller → Service → Repository).

Base de Datos — MySQL 8.0 en VirtualBox

Instancia MySQL corriendo en VM Ubuntu (VirtualBox). Diseño con CHECK constraints, claves foráneas, índices únicos y datos reales de temporadas 2023–2026.

Fases de Desarrollo

1

Planteamiento del Problema

Definición del dominio del sistema, alcance del proyecto, objetivos y requerimientos funcionales del sistema de estadísticas F1.

2

Identificación de Entidades

Análisis del dominio para identificar las entidades principales: pilotos, escuderías, circuitos, temporadas, grandes premios, sesiones y resultados.

3

Diagrama MERE

Construcción del Modelo Entidad-Relación Extendido (MERE_F1.drawio / MERE_F1.pdf) con entidades, atributos, relaciones y cardinalidades completas.

4

Modelo Relacional

Conversión del MERE al modelo relacional: definición de tablas, claves primarias, claves foráneas y restricciones de integridad.

5

Normalización

Aplicación de las formas normales (1FN, 2FN, 3FN) para eliminar redundancias y garantizar la integridad de los datos.

6

Script SQL (DDL + DML)

Implementación del DDL con 17 tablas, constraints CHECK, claves foráneas e índices únicos en MySQL 8.0. DML con datos reales de 4 temporadas.

7

Reducción a Tablas

Proceso formal de reducción del modelo relacional a tablas físicas, documentando las decisiones de implementación.

8

Implementación Full-Stack + VirtualBox

Despliegue de MySQL en VM Ubuntu (VirtualBox), API REST con Spring Boot 3 y frontend React 18 + TypeScript con visualizaciones de estadísticas.

Conceptos de BD Aplicados

Modelo MERE: Diseño conceptual completo con notación extendida
Normalización: 1FN, 2FN y 3FN aplicadas al modelo
Integridad referencial: 15+ claves foráneas con ON DELETE
CHECK constraints: Validaciones de dominio en MySQL
Índices únicos: Restricciones UNIQUE para consistencia
Herencia / Especialización: Patrón persona → piloto / usuario
Relaciones N:M: Contratos piloto ↔ escudería por temporada
ORM: Hibernate mapeando el modelo relacional a Java
Virtualización: Servidor MySQL en VM Ubuntu dedicada
API REST: Exposición del modelo de datos vía HTTP/JSON
